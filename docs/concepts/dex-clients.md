# Dex clients

patchy registers its dex clients itself, as `DexClient` objects. The platform's
[dex-client-controller](https://oss.bitwisemedia.uk/dex-client-controller/) turns them into dex clients through dex's
gRPC API.

They need a flux-manifests release that runs the controller beside dex, and they render only when `dex` is in
`PLATFORM_COMPONENTS`: on a dex-less cluster the `DexClient` CRD doesn't exist.

| `DexClient` (in `patchy`) | Client id       | Kind                     | When                       | Consumed by                                                                                |
| ------------------------- | --------------- | ------------------------ | -------------------------- | ------------------------------------------------------------------------------------------ |
| `status`                  | `patchy-status` | confidential             | dex elected                | the status server: `status-dex-client` Secret, generated by the controller                 |
| `evolve`                  | `patchy-evolve` | public (PKCE, no secret) | dex elected and evaluation | the evaluation API's `auth.config.oidc.clientID`; evolve reads it from `/api/v1/auth/info` |

Client ids are the controller's `<namespace>-<name>` default. The platform's kyverno policy holds any explicit id to the
same `patchy-` prefix.

## The status server's auth mount

The status server's auth mount is a projection of two sources:

- the `patchy-status-auth` ConfigMap: the secretless `config.yaml`, shipped beside the `DexClient`;
- the `clientSecret` key of `status-dex-client`, mounted as the `client-secret` file that `config.yaml` points at.

The chart mounts a single Secret, so a postRenderer on the patchy HelmRelease rewrites the volume. On a dex cluster the
client Secret is required, so the pod waits for the controller rather than starting half-configured.

## Rotating the status client's secret

Delete `status-dex-client`. The controller generates a new one and replaces the client in dex. Then restart the status
server, which reads the file at startup:

```sh
kubectl -n patchy delete secret status-dex-client
kubectl -n patchy rollout restart deployment patchy-status-server
```

Coming from the cluster module's `dex_clients`? See [To DexClient](../upgrading/dex-client.md).
