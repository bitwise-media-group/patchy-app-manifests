// AN APPLICATION, NOT A PLATFORM COMPONENT

The platform carries nothing patchy-specific. A cluster that doesn't run patchy never sees its IAM, secrets or SSO wiring.

One signed image

The chart releases, secret syncs, RBAC bindings and image-verification policy ship together as manifests/patchy, pushed to GAR and ECR and signed keylessly by the publish workflow.

Self-owned after seeding

terraform seeds the patchy-manifests input provider and ResourceSet once; the image ships the same two objects, so the first reconcile adopts them and flux owns them from then on.

Follows version tags

The seed tracks PATCHY_MANIFESTS_SEMVER and turns the newest match into a digest-pinned, signature-verified OCIRepository. Channel tags are for humans.

Out-of-cluster halves

The per-cloud modules create the credential containers, the IAM grants and the patchy-vars ConfigMap through the cluster module's modules/application.

Self-registered SSO

On dex clusters the image registers its own DexClients — the status server's and evolve's — and the platform's dex-client-controller turns them into dex clients.

Verified by exactly one rule

A PolicyException moves patchy's namespaces off the platform signature rule and verify-patchy-signature re-verifies them — the check moves, it is never dropped.
